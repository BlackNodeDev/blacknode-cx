01 // EXECUTION ARCHITECTURE

The Zero-Placeholder Pipeline

Core is built to take architectural intent and run a closed loop — not a one-shot snippet. Scan context, generate typed code, audit for secrets, and hand back a complete, executable file. That cycle lives in Core, not on this page.

04 // STUDIO OS

Docs, Grid, Vault, AI

An offline studio fused into Core. Local-first, keyless, and stored per user on the device.

DOCS
Offline markdown

Source on one side, rendered reading view on the other. Autosaves locally.

GRID
Formula sheet

A real engine for refs, ranges, SUM, IF, and the usual sheet functions. Export to CSV.

VAULT
On-device, per user

Secrets stay on the device and are redacted in the audit log. Nothing is uploaded.

NODECORE AI
Same brain tier

Tools-first retrieval over docs and sheets, then synthesis. No raw keys in the client.

05 // GUARDRAILS

Allow, Ask, Deny

Sensitive actions are gated in Core. Approvals happen there — this page does not run the engine, and it cannot approve anything on your behalf.

POLICY
ALLOW // ASK // DENY

Each rule can be cycled in Core. Ask prompts a one-time or session approval; deny blocks the action.

AUDIT LOG
Hash-chained

Every event lands in a tamper-evident chain you can verify and export.

VERIFIER
Independent second judge

A compile can face a second pass with no prior context from the first brain.

SECRETS
Zero credentials stored

The page does not keep organisation fingerprints or keys in code.
