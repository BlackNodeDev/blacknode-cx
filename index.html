03 · How it works

A closed loop, not a snippet.

Core takes intent and runs it all the way through. The output is a complete file you can run.

01 · SCAN

Read the workspace

Multi-file context first, so the plan fits the code that already exists.

in: goal + project
02 · GENERATE

Write typed code

Statically-typed output across files, delivered as diffs. No TODOs left behind.

out: unified diff
03 · AUDIT

Check for risk

OWASP-style checks and a zero-secret scan before anything moves on.

gate: security review
04 · VERIFY

Prove it runs

An independent verifier re-checks the build, then it runs in the live viewport.

status: ready to deploy
Typical AI output
Isolated snippets

05 · Guardrails

Autonomous, never unsupervised.

Bots handle safe changes on their own. Anything sensitive stops and waits for you, inside Core.

Allow, ask, deny

Every sensitive action has a rule. Ask pauses for a one-time or session approval; deny blocks it outright.

ALLOWASKDENY

Hash-chained audit log

Every event lands in a tamper-evident chain you can verify and export.

Independent verifier

A compile can face a second judge with no context from the first, so mistakes don't grade themselves.

Zero stored credentials

No keys in the page, no keys in code. Secrets stay in an on-device vault.
