01 · The team

Who does what.

The bots are the roles inside Core's Orchestrator. Planning, coding, review and operations, plus a bot that ships.

Planning

Architect Bot

Turns a goal into services, state schemas and a dependency graph before a file is written.

Hands off to Compiler Bot
  • Breaks a request into decoupled pieces
  • Drafts the node topology and state schema
  • Hands a typed plan to Compiler Bot
Coding

Compiler Bot

Writes statically-typed code across files and returns unified diffs. No TODO stubs.

Hands off to Security Bot
  • Scans the whole workspace for context
  • Generates typed GDScript 4.x
  • Returns patches as unified Git diffs
Review

Security Bot

Runs OWASP-style checks and a zero-secret scan on every change.

Hands off to Launch Bot
  • Flags common vulnerability patterns
  • Blocks credentials from landing in code
  • Sends the build to an independent verifier
Operations

Triage Bot

Reads runtime logs, isolates the failing line and proposes a diagnostic patch.

Hands off to Compiler Bot
  • Parses runtime logs and stack traces
  • Pins the failure to a line
  • Proposes a patch for review
Ship

Launch Bot

Syncs the scene, exports the build and asks for your OK before anything high-impact ships.

Hands off to you, for approval
  • Syncs the Godot scene tree
  • Exports the finished build
  • Pauses with an approval card before shipping

05 · Guardrails

Autonomous, never unsupervised.

Bots handle safe changes on their own. Anything sensitive stops and waits for you, inside Core.

Allow, ask, deny

Every sensitive action has a rule. Ask pauses for a one-time or session approval; deny blocks it outright.

ALLOWASKDENY

Hash-chained audit log

Every event lands in a tamper-evident chain you can verify and export.

Independent verifier

A compile can face a second judge with no context from the first, so mistakes don't grade themselves.

Zero stored credentials

No keys in the page, no keys in code. Secrets stay in an on-device vault.
